## Create

<Steps>

1. Drop the files to protect (or a folder) onto the table. Each file is hashed as soon as it is added.

2. Choose the hash type below the table: **SFV**, **MD5**, **SHA1**, **SHA2** or **SHA3**.

3. Click **Save as ...** and choose where to save the file.

</Steps>

| Toggle | Algorithm | File |
| --- | --- | --- |
| SFV | CRC32 | `.sfv` |
| MD5 | MD5 | `.md5` |
| SHA1 | SHA-1 | `.sha1` |
| SHA2 | SHA-256 | `.sha256` |
| SHA3 | SHA3-384 | `.sha3` |

The paths in the saved file are relative to the folder you save it in, so it can be saved anywhere (files on
another drive keep their full path). SFV files use Windows line endings, MD5 and SHA files use Unix line endings
like `md5sum`. Files whose hash is still being calculated are left out, with a warning.

Changing the hash type recalculates the table. **Clear** empties it; `Delete` removes the selected rows.

## Verify

<Steps>

1. Drop a checksum file (`.sfv`, `.md5`, `.sha1`, `.sha256` or `.sha3`) or the whole folder onto the table. Checksum
   files are verified against the files next to them, and every other file is hashed.

2. Read the **State** column for each file:

   | State | Meaning |
   | --- | --- |
   | OK | The hash matches |
   | WARNING | The CRC32 in the file name (e.g. `[A1B2C3D4]`) does not match the file |
   | ERROR | The checksum file and the file disagree, or the file could not be read |

</Steps>

A CRC32 in a file name (for example `[A1B2C3D4]`) is checked too, so a release can be verified without a
checksum file.
